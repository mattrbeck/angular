# Ambiguous Pipe Function Call

This diagnostic detects bare function calls in templates that ambiguously match both an in-scope pipe and a member of the component class.

```html
<!-- `format` is both an imported Pipe and a method on MyComponent -->
<div>{{ format(dateValue) }}</div>
```

## What's wrong with that?

When using functional pipe syntax (such as `format(value)`), Angular resolves the identifier to the imported pipe by default. If your component class also defines a method or property with the same name, this bare call can create confusion or unintended shadowing of your component method.

## What should I do instead?

1. **If you intended to call the component method:**
   Add `this.` to explicitly target the component instance:

   ```html
   <div>{{ this.format(dateValue) }}</div>
   ```

2. **If you intended to invoke the pipe:**
   Rename the component member to avoid naming clashes:

   ```typescript
   formatCustom(date: Date) { ... }
   ```

3. **Using automated migration:**
   Run the migration schematic to update templates and automatically resolve collisions with `this.`:
   ```bash
   ng generate @angular/core:pipe-function-calls
   ```

## Configuration requirements

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) must be enabled for any extended diagnostic to emit.

## What if I can't avoid this?

This diagnostic can be disabled by editing the project's `tsconfig.json` file:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "ambiguousPipeFunctionCall": "suppress"
      }
    }
  }
}
```

See [extended diagnostic configuration](extended-diagnostics#configuration) for more info.
